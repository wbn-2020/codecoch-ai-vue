# CodeCoachAI 用户工作台聚焦驾驶舱设计规格

## 目标

将用户工作台从“所有系统能力同时铺开”的长页面，重构为“一个明确主行动 + 紧凑上下文 + 今日行动时间线 + 按需展开的证据与工具”。保持现有业务能力和可信推荐边界，不改变接口数据来源。

## 已确认方向

采用用户选定的组合方案：

- 以“聚焦驾驶舱”为页面骨架。
- 保留“行动时间线”的顺序感和完成感。
- 首屏不再展示大段产品说明、重复统计和白色卡片墙。
- 深色主题原生实现，不再依赖浅色页面样式被全局 `!important` 二次覆盖。

## 用户任务

用户打开工作台后应在数秒内回答四个问题：

1. 今天最应该做什么？
2. 为什么现在做？
3. 后面还有哪些行动？
4. 推荐依据是否可信，缺失信息是什么？

## 信息架构

### 首屏

首屏最多包含三个一级区域：

1. **主行动与上下文**
   - 左侧：唯一主行动标题、简短原因、预计耗时、一个主 CTA。
   - 右侧：目标岗位、资料接入、最近报告、风险缺口四个紧凑信号。
   - 不重复展示 Hero “今天先做”和独立“今日主行动”卡。

2. **今日行动时间线**
   - 最多展示三条行动。
   - 第一条为主行动，后续按推荐顺序排列。
   - 每条只显示标题、状态、来源摘要和耗时。
   - 完成、跳过和进入动作沿用现有业务能力。

3. **推荐依据摘要**
   - 展示支持当前主行动的可信来源和缺失项。
   - “依据、来源、边界、收益”等长信息默认折叠。
   - 没有可信依据时明确降级，不生成能力结论。

### 条件区域

- 有今日到期、逾期或待跟进投递时，在时间线中插入投递行动。
- 没有投递行动时，不渲染完整投递统计大区块。
- 新用户资料不足时，使用紧凑 onboarding 提示，不与完整正常工作台同时展示四卡引导。
- 局部错误靠近对应模块展示，不占用全宽大型错误卡。

### 次级内容

以下内容合并到一个“资料与工具”区域，默认收起：

- 六步资料引导。
- 简历与岗位资料完整度。
- 最近报告与错题。
- 最近产物。
- 面试前工具。
- Agent loop 的详细统计。

## 去重规则

- `primaryTask.title` 在同一断点最多出现一次。
- 同一行动意图最多有一个主按钮。
- 目标岗位不再同时出现在 Hero、目标卡、首日证据和资料完整度四处。
- Agent loop 与行动队列合并为行动时间线摘要。
- 风险缺口、首日证据和 AI 推荐依据合并为推荐依据摘要。
- 最近产物与最近反馈进入同一次级区域。

## 视觉系统

### 物理场景

用户在桌面浏览器中进行 20-40 分钟的求职训练和投递管理，需要低眩光、长时间可读、快速扫描的深色工作界面。

### 色彩策略

采用 restrained 深色产品界面：

- 页面背景：接近黑色的中性蓝灰，不使用装饰网格、光斑或大面积渐变。
- 一级表面：不透明深蓝灰。
- 二级表面：更暗一级，用于列表和折叠区域。
- 主色：克制的蓝色，仅用于主 CTA、当前选择和焦点。
- 成功、警告、错误分别使用低饱和绿、琥珀和红。
- 白色仅用于文字和真实文档预览，不作为 Dashboard 卡片背景。

建议令牌：

```scss
--user-bg: #0b1018;
--user-surface: #111925;
--user-surface-muted: #0e1621;
--user-surface-raised: #162131;
--user-border: #273140;
--user-border-strong: #39475a;
--user-text: #eef2f7;
--user-text-secondary: #b8c1ce;
--user-text-muted: #8d99aa;
--user-primary: #5b8def;
--user-primary-hover: #75a7ff;
--user-success: #58c995;
--user-warning: #e8ad58;
--user-danger: #e77987;
```

### 层级与容器

- 首屏只有主行动容器具备明确抬升层级。
- 其他区域依靠标题、分隔线、表面层级组织，不使用卡片嵌套卡片。
- 默认一级带边框容器不超过六个。
- 容器圆角 8px，按钮圆角 6-8px。
- 移除发光阴影、装饰性 backdrop blur 和每卡渐变。

### 字体与密度

- 保持现有系统 sans 字体。
- 页面标题 24px，模块标题 16-18px，正文 13-14px，辅助文字 12px。
- 不使用 viewport 流式字号。
- 主行动说明行长控制在 65-75 个中文字符内。

### 交互

- 主行动只有一个主要按钮。
- 推荐依据通过原生折叠区域展开。
- 次级资料通过一个统一折叠区域展开。
- 所有自定义按钮提供 `:focus-visible`。
- 动效仅用于展开、状态切换和 hover，时长 150-220ms。
- `prefers-reduced-motion` 下取消位移。

## 响应式

### 桌面 1366x768

- 首屏可见主行动、四个状态信号、三条时间线和推荐依据摘要。
- 主行动/信号为 2 栏，时间线/依据为 2 栏。

### 平板

- 主行动和信号上下排列。
- 时间线保持单列，依据放在其后。

### 手机 390x844

- 只显示紧凑主行动、状态信号 2x2、行动时间线。
- 底部行动栏高度不超过 72px，只保留主 CTA。
- 不复制状态、边界和两个快捷入口。
- 次级资料默认收起。

## 状态与错误

- Loading 使用局部 skeleton/占位行，不用整页遮罩。
- 无任务时提供“生成今日计划”一个主入口。
- 无投递行动时不渲染空统计卡墙。
- 无目标岗位时把“设定目标岗位”作为上下文动作，不覆盖主行动区。
- 部分接口失败时保留其他模块和静态入口。

## 验收标准

1. 1366x768 无滚动可见主行动、CTA、目标岗位、时间线和推荐依据摘要。
2. 首页一级带边框容器默认不超过六个。
3. 页面不出现纯白 Dashboard 背景，不出现白字白底。
4. `primaryTask.title` 同一断点只出现一次。
5. 无投递行动、无任务和资料不足时不渲染空卡片墙。
6. 普通文字对比度不低于 4.5:1，大字不低于 3:1。
7. 390x844 无水平滚动，底部行动栏不遮挡页面末尾。
8. 200% 缩放下文字和按钮不裁切。
9. 所有自定义按钮可键盘访问并具备明显焦点样式。
10. 桌面和手机视觉回归截图无突兀白区、卡片嵌套和大面积空白。

## 非目标

- 本轮不重构其他用户页面的完整信息架构。
- 本轮不引入新的前端 UI 框架。
- 本轮不改变推荐算法或工作台接口。
- 本轮不增加营销型 Hero、装饰插画或大面积动效。
